## 3. 公式与参考配置

### 3.1 标准 MHA/GQA/MQA KV Cache

```text
KV bytes = 2 × L × H_kv × d_h × S × B × bytes_per_element
d_h = hidden_size ÷ H_q
```

- `2` 表示 K 与 V 两份持久缓存。
- `H_kv` 必须使用目标模型公开配置；GQA 的 `H_q/4` 只作为无参考配置时的可调整示例，不是通用事实。
- 结果是持久缓存理论载荷，不包含 allocator、块表、对齐、碎片和框架预留。

### 3.2 MLA KV Cache

```text
MLA bytes = L × S × B × (kv_lora_rank + qk_rope_head_dim) × bytes_per_element
```

DeepSeek-V2 参考配置使用：

- `kv_lora_rank = 512`
- `qk_rope_head_dim = 64`
- 持久缓存宽度：`576`
- Q/K Head 维度：`qk_nope_head_dim + qk_rope_head_dim = 128 + 64 = 192`

原页面曾把 `hidden_size / num_heads = 5120 / 128 = 40` 显示成 MLA Head 维度。该值不是 DeepSeek-V2 MLA 的公开 Q/K Head 维度，现已改为显示 `192`。

### 3.3 参考结果

| 参考配置 | 场景 | KV Cache | 纯权重理论载荷 |
|---|---|---:|---:|
| Llama 3 8B | FP16、8,192 Token、Batch 1、GQA | 1.00 GiB | 14.90 GiB |
| Llama 3 70B | FP16、8,192 Token、Batch 1、GQA | 2.50 GiB | 130.39 GiB |
| DeepSeek-V2 | FP16、128,000 Token、Batch 1、MLA | 8.24 GiB | 439.58 GiB |

权重值按模型档位标称参数量 × 每元素字节数换算为 GiB，仅代表纯权重理论载荷。真实权重文件、量化格式与运行显存可能不同。

### 3.4 量化容量下界

70B 参数示例：

| 格式 | 理论字节/参数 | 纯权重下界 |
|---|---:|---:|
| FP16 | 2 | 130.39 GiB |
| INT8 | 1 | 65.19 GiB |
| INT4 | 0.5 | 32.60 GiB |

INT8/INT4 数值是打包权重的理论下界，不包含 scale、zero point、group metadata、对齐和运行时工作区；容量比例不能直接推导同等性能比例。

## 4. 已修正的技术表述

- Dense：不再使用“参数量等于每步计算量”。改为“每个 Token 使用固定稠密层路径”，并明确参数量、激活参数口径与 FLOPs 不是同一量纲。
- FlashAttention：明确它是数学上的精确 Attention，不采用稀疏近似；同时保留浮点归约顺序可能产生微小舍入差异的边界。
- Speculative Decoding：不再写固定 `2～3×` 提速或“正确 Token”。改为按接受/拒绝规则保持目标分布，收益取决于接受率和额外开销。
- MTP：不再宣称必然加速或提高训练收敛；改为辅助未来位置预测，并可在受支持实现中提供推测候选。
- 结构化输出：不再宣称“100% 语义正确”。约束解码只能在实现支持与约束覆盖范围内保证语法合规，字段语义和业务规则仍需验证。
- 量化：不再按 INT8/INT4 位宽直接判断精度损失或端到端速度。
- NVLink/PCIe：不再使用脱离代际与拓扑的绝对带宽判断；比较需注明 GPU、链路数、NVSwitch、PCIe 代际和服务器拓扑。
- Continuous Batching、Shared Expert、Expert Choice：移除“GPU 一定不空闲”“保证基础能力”“天然均衡”等绝对化表达。

## 6. 链路诊断扩展审计

- 五类症状均扩展为 8 项可选证据和 6 个候选原因，共 40 项证据、30 个候选原因。
- 证据分为“阶段证据”和“辅助证据”；排序先看阶段证据，再综合支持信号与明确反证，结果只表示验证顺序，不表示统计概率。
- 每个候选原因均包含：可解释范围、支持信号、待补阶段证据、明确反证、削弱条件、验证步骤和验证后的处理方向。
- TTFT 明确拆分客户端入口、queue、Prefill 与首包返回；TPOT 与 ITL 明确区分；吞吐明确区分 offered load、原始吞吐与满足 SLO 的 goodput。
- OOM 明确区分权重、KV Cache、临时张量/工作区、缓存分配器、图内存池与框架外分配；`reserved > allocated` 不单独作为碎片结论。
- 诊断依据采用 vLLM Production Metrics、PyTorch CUDA Memory、NVIDIA CUDA Graph 与 NCCL 官方文档；页面保留对应链接与工具边界。
- 自动数据审计确认：所有证据引用、全景图模块 ID、知识条目 ID 均有效；阶段证据均为候选支持信号子集，反证与支持信号无重叠。
