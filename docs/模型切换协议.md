# 开发模型切换协议

> 本协议约定：开发过程中遇到“重活”或“视觉需求”时，暂停工作并提醒用户切换模型。

## 一、背景

用户使用两个模型辅助开发：

- **DeepSeek V4 Flash**：默认主力，Codex 原生接入、成本低，适合日常迭代
- **Kimi K2.7 Code**：编程特化 + 原生视觉输入，用于重活与视觉需求

## 二、触发条件

### 重活（切换 K2.7 Code）

满足以下任一条件即视为重活：

- 一次修改涉及 **3 个以上文件** 的联动
- 任务状态超过 3 个且互相影响（复杂状态机 / 异步时序）
- 长链路逻辑：多步骤动画编排、诊断流程、前后端交互
- 组件库封装 / hooks 编写（全局影响大）
- 大范围重构（如静态页迁移成 React 组件）

本项目已知重活任务：

| 任务 | 原因 |
|---|---|
| M2 推理流水线模拟器 | 动画状态机、暂停/回放/对比、时序复杂 |
| M3 参数实验室 | 滑块联动多图表实时计算 |
| M5 推理侦探 | 多场景状态机 + 点击诊断 + 因果链 |
| M6 智能体 | RAG 检索、Prompt 组装、API 错误处理 |
| M1 全景图迁移 | 几十个文件联动调整 |

### 视觉需求（切换 K2.7 Code）

满足以下任一条件即视为视觉需求：

- 需要“看着现有 HTML 页面 / 设计稿 / 截图”还原成 React 组件
- 需要根据浏览器截图定位和修复 UI 样式问题
- 需要根据参考图实现动画效果
- 需要生成/处理界面相关的视觉材料

## 三、触发时的行为

1. **暂停当前开发工作**
2. 明确提醒用户：“当前任务属于重活/视觉需求，建议切换 Kimi K2.7 Code”
3. 说明为什么（列出触发条件）
4. 等用户确认切换后再继续

## 四、默认模型分工

```text
重活 / 视觉需求 → Kimi K2.7 Code
日常迭代（改文案、简单组件、常规问答、批量轻量任务）→ DeepSeek V4 Flash
```

## 五、维护

- 新增模块或任务时，同步评估是否属于重活
- 触发条件变化时，更新本协议
